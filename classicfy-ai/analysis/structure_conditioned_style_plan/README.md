## 연결 단계의 계획과 진행

아래는 원래 단계별 계획이다. 2026-10-13에 BWV 848용 XML 두 파일을 해시 대조 후 준비하고,
최소 bridge·타이/상태 처리·원래 beat/Dynamics 결합·그림과 독립 검증을 완료했다.
관련 테스트 61개 통과, 수치 147,284개 독립 검산 통과. 전체 110개 XML 입력 준비와 55 grid/570연주 확장은 남아 있다.
3단계의 반복·변형 처리부터 다음 단위로 진행한다. 입력 누락/미구현으로 적힌 아래 설명은 계획 수립 당시의 상황이며,
현재 BWV 848 입력 및 첫 bridge의 상태는 위 보고서를 기준으로 한다.

### 0. 고정 입력 준비 및 사전 확인

1. [works.csv](../score_structure_inputs/works.csv)와 [nasap_works.csv](../score_structure_inputs/nasap_works.csv)의 대상 XML과 해시를 확인한다. 첫 구현 대상인 BWV 848 Fugue의 ASAP/nASAP XML은 존재와 해시 일치를 재확인했다. 다른 작품으로 확장할 때 해당 입력도 확인한다.
2. 새 입력은 기존 목록의 `xml_sha256`과 대조한다. 버전이 다르면 해당 차이를 기록하고 기존 입력 목록이나 보고서를 덮어쓰지 않는다.
3. 메타데이터·annotation·score MIDI·match·기존 feature와 grid hash를 함께 점검한다. 새 입력은 XML·MIDI·match·annotation 사이의 연결 근거가 확인된 경우에 사용한다.
4. 검증은 새 출력 경로에서 실행한다. XML 공급처가 확인되기 전에는 다른 XML로 자동 대체하지 않는다.

입력 준비 후 재현 명령(저장소 루트):

```bash
task_validation_dir=$(mktemp -d /tmp/classicfy-issue16-loader-validation.XXXXXX)
.venv/bin/python classicfy-ai/scripts/validate_musicxml_loader.py \
  --asap-root ../datasets/ASAP --nasap-root ../datasets/nASAP \
  --out "$task_validation_dir"
```

완료 기준: 110개 입력의 해시 대조와 로딩 결과를 확보하고, 누락·변형이 있으면 대상과 원인을 명시한다.

### 1. 입력 인터페이스와 연결 규칙 정의

예정 파일: `src/preprocessing/score_metadata.py`, `src/preprocessing/score_beat_bridge.py`.

- 별도 score metadata 인터페이스에서 원본/nASAP XML 경로, score MIDI, 원본 마디 대응표, grid 및 입력 해시를 제공한다. 기존 `AsapSample` 호출 결과와 feature 추출을 보존한다.
- 연결 레코드는 원본 XML ID·내부 note ID·원본 match ID·part/voice/staff·쓰인 마디 순서·진행 회차를 구분한다. ID 접미사 의미를 먼저 확인하고 원문을 보존한다.
- 좌표는 쓰인 XML quarter 위치, 반복을 반영한 score MIDI quarter 위치, ASAP 원래 interval index, 연주 초를 각각 이름과 단위로 명시한다.
- beat별 `status`, 연결 방법, 근거, 지원 음 수, coverage와 실패 사유를 저장한다. 불확실하거나 충돌하는 연결을 임의로 하나 선택하지 않는다.
- match의 원본 마디:박 정보 등이 추가로 필요하면 선택 필드 또는 별도 레코드로 확장하며 기존 `load_match()` 호출 호환성을 검증한다.

완료 기준: 반복·못갖춘마디·마디 번호 중복·불규칙 beat·결측을 표현할 수 있는 입출력과 합성 fixture를 정의한다.

### 2. 반복 없는 악보 연결

1. nASAP XML ID를 연결 후보로 사용하고 XML의 음높이·악보 위치·길이와 match의 악보 음을 대조한다. deletions도 악보 구조 연결 근거로 보존한다.
2. score MIDI의 tick/PPQ·tempo map으로 score beat의 초 좌표를 quarter 위치로 바꾼다. XML의 시작점·못갖춘마디·표기 길이와 MIDI 좌표 차이를 실제 음 대응으로 확인한다.
3. 확인한 악보 구조를 원래 ASAP `[beat[i], beat[i+1])` 구간에 배정한다. beat 수가 B개이면 출력은 B−1개 원래 구간을 유지한다.
4. 마디 대응표는 추가 확인 근거로 사용한다. 첫 마디 `0`이나 `1-2` 표기를 일괄 숫자 보정하지 않는다.
5. 기존 압축 feature는 `shared_indices`로 원래 위치를 복원해 구조와 결합한다. masked 값은 표현 계산에서 제외하며 정의되지 않은 구조값을 0으로 바꾸지 않는다.

완료 기준: 일반 악보와 못갖춘마디·박자 변화 사례에서 음높이·위치·구간 경계가 독립 재계산과 일치하고, 모든 미대응 항목에 상태가 있다. 허용 오차는 MIDI tick 및 입력 정밀도에 근거해 검증 전에 정한다.

### 3. 반복 회차와 악보 변형 확장

필수 점검 대상은 `24-1_no_2_repeat`, `26-1`, `31-2`, `32-1`의 4악보·23연주다.

- 쓰인 마디를 반복 기호만으로 펼쳐 정답으로 간주하지 않는다. 실제 score MIDI의 진행과 match 악보 음의 대응으로 회차 및 생략·추가 반복을 확인한다.
- 같은 XML 음이 여러 진행 위치에 나타나면 각 occurrence를 따로 보존한다. 같은 작품명이어도 grid/변형이 다르면 연결표를 합치지 않는다.
- 대응표가 없는 구간은 검증된 음 연결로 보완한다. 근거가 부족하면 `unresolved`/`ambiguous` 등의 상태와 지원 수를 남긴다.
- `bR`, 0폭 구간, 반복 점프와 결측의 양쪽을 변화량·지속·상관 계산에서 이어 붙이지 않는다.

완료 기준: 4악보를 모두 점검하고, 성공·부분 연결·미해결 범위와 원인을 보고한다. 반복 회차가 합쳐지거나 다른 grid를 공유하는 잘못된 대응이 테스트에서 검출되어야 한다.

### 4. 독립 계산 및 정렬 시각 검증

예정 산출물: `scripts/validate_score_beat_bridge.py`, `tests/unit/preprocessing/test_score_beat_bridge.py`,
`tests/integration/test_score_structure_pipeline.py`, `analysis/score_beat_bridge/`.

- 사례 선정 규칙을 feature나 검색 점수를 보기 전에 고정한다. 반복 없는 BWV 848 사례를 시작점으로 두고, 못갖춘마디·박자 변화·불규칙 beat 사례는 입력 목록에서 해당 속성별 이름순으로 고른다. 반복 4악보는 모두 포함한다.
- 합성 테스트에서 ID 충돌·접미사, 양의/음의 시작점 차이, 반복 회차, 첫 마디 0, 마디 번호 중복, 구간 경계, 0폭 beat, mask/index 복원과 미지원 연결의 명시적 상태를 검증한다.
- 별도의 tick/PPQ 계산과 원본 XML·match 대조로 음높이·위치·회차·구간 배정을 검산한다. bridge 함수의 출력끼리만 비교하지 않는다.
- figure에는 같은 원래 beat 축의 마디/회차·음표/slur·연주 feature와 결측/미대응 구간을 표시한다. 그림 옆의 CSV로 수치를 확인할 수 있게 한다.
- 전체 55 grid·570연주의 연결 가능률과 실패 유형을 집계한다. 모든 연결을 100%로 강제하지 않고 검증된 범위만 후속 분석에 사용한다.
- `protocol.json`, `notes.csv`, `beat_map.csv`, `coverage.csv`, 진단·figure·독립 검증 결과와 provenance를 저장한다. 기존 원본 feature와 정규화 산출물이 바뀌지 않았는지 확인한다.

전체 연결 단계의 완료 조건은 같은 beat 축의 연결이 수치·그림으로 검증되고,
반복·변형·실패 상태 및 사용 가능한 표본 범위가 공개되는 것이다.

## 이후 순서와 판단 기준

| 단계 | 작업 | 완료 또는 다음 단계 진입 기준 |
|---|---|---|
| 프레이즈 | slur·쉼·종지 단서로 후보를 만들고 악보 기준 검수. 경계·상대 위치·근거·불확실성 저장 | slur와 프레이즈를 구분하고 미확정 경계를 표시. 검수한 구간만 사용 |
| 긴장도 | 악보 음높이·길이·조성으로 세 지표 계산. 계산 구간·mode 출처·추정 불확실성 정의 | 작은 예제 독립 계산 및 조성/구간 검증. mode 미상이나 계산 불가를 0으로 대체하지 않음 |
| 반응 표현 | 프레이즈 시작·중간·끝, 긴장 상승·완화 구간의 개별 시간 및 공동 변화 특징 | 공통 반응과 연주별 잔차의 정의·단위·지원 수 고정. 경계/결측을 넘는 차분 금지 |
| 비교 설계 | 전곡 기준, 고정 길이 구간, 프레이즈, 긴장도, 결합 조건 | 공통 cohort·query/gallery·split·검색/평가 구간·K·가중치·주 지표·대조를 실행 전에 고정 |
| 검색 평가 | 기존 기준 재실행, 구조 조건 Top 5, 메타데이터 차이와 별도 구간 일치, 대조 | E-L/E-T/E-R와 구조 반응 평가 모두 공개. 개선·악화·지원 부족을 함께 보고 |

프레이즈와 긴장도는 beat 연결 검증 이후 서로 독립적으로 진행할 수 있다. 연주 feature로 경계나 긴장도를 정하지 않는다.
BWV 848의 작은 경계 배정 차이와 음별 미대응은 후속 작업을 중단할 조건으로 두지 않는다.
모든 note-on과 MIDI 길이의 100% 일치를 선행 목표로 확대하지 않고, 기존 계획을 진행하며
미대응 세 음·큰 시각 차이 두 사례를 표시해 처리한다. 구조에 따른 반응 측정치를 정의한 뒤
경계 이동과 경계 사건 포함/제외에 대한 결과 민감도를 검증한다.
첫 비교는 해석 가능한 요약·거리 표현으로 시작하고, 새 신경망은 그 비교에서 필요한 근거가 생긴 뒤 별도로 계획한다.

평가의 기본 규칙은 [기존 검색 설계](../metadata_retrieval_design/README.md)와
[구조 기반 후속 방향](../metadata_retrieval_results/FOLLOWUP.md)을 따른다.
구조 가능 표본으로 좁히면 같은 표본에서 기존 전곡 기준도 다시 실행한다. 기존 69.1점과 새 부분 표본의 점수를 직접 빼지 않는다.
검색 입력과 평가에 같은 구간의 표현값을 사용하지 않는다. 구조 자체만 사용한 조건과 구조 대응을 섞은 조건,
같은 작품의 다른 연주·길이/coverage·후보 수·표현 차원/결합 가중치 대조를 포함한다.
표본이나 임계값은 결과를 보고 유리하게 바꾸지 않으며, 계산상의 일치를 사람의 청취 유사성·선호 성공으로 해석하지 않는다.

## 유지할 추적 방식

각 구현 묶음이 끝날 때 이 문서의 요구사항별 상태·근거 커밋·검증 결과를 갱신한다.
완료 기준을 충족한 항목만 완료로 바꾸고, 보고서 및 독립 검증 링크를 추가한다.
계획 수립 이후 첫 bridge 구현과 검증을 완료했다. 반복·변형·프레이즈·긴장도 및 학습·검색 실험은 후속이며 GitHub TODO는 변경하지 않았다.
