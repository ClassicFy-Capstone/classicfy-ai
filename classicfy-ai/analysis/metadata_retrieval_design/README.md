# 다른 작품 검색: 메타데이터와 구분되는 연주 스타일 축의 실험 설계

**목표는 두 가지를 함께 확인하는 것이다.** 같은 연주에서 K개를 검색할 때
메타데이터 추천과 다른 결과를 만들고, 그 차이가 우리가 정의한 스타일에 따라 일관적인가?
단순히 다른 목록을 만드는 것과 유용한 연주 정보를 이용하는 것은 구분한다.

이 문서는 **실행 전에 작성한 설계의 기록**이다. 이후 조건을 바꾸지 않고 실행한
[검색 결과·대조·그림·독립 검증](../metadata_retrieval_results/README.md)을 별도로 저장했다.
실행 설정은 [protocol.json](protocol.json)에 기록했다.
현재 데이터 구성과 출처 hash는 [design_provenance.json](design_provenance.json)에 기록했다.
최종 구간 cohort와 검색용 scale은 결과 폴더의 preflight·scales 기록에 있다.
이후 결과는 별도 `metadata_retrieval_results/`에 저장하며 이전 실험을 덮어쓰지 않는다.

## 1. 이전 실험과 달라지는 질문

[이전 실험](../metadata_information_results/README.md)은 전곡 임베딩에서 특정 시간 측정치를
선형 예측할 수 있는지 검사했다. 이번에는 **실제로 다른 작품의 연주를 검색**한다.

| 질문 | 확인할 내용 | 이 결과만으로 말할 수 없는 것 |
|---|---|---|
| 메타데이터와 다른 후보를 가져오는가? | 연주·작품군 Top K 겹침, 새 후보 비율, 후보의 메타데이터 구성 | 스타일이 더 잘 맞거나 무작위와 다르다는 결론 |
| 다른 결과가 스타일상 의미 있는가? | 검색에 쓰지 않은 구간에서의 스타일 일치, 조건부 무작위 대조 | 사람이 느끼는 유사성·사용자 선호 |
| 시간/관계 보강이 의도대로 작동하는가? | 평균·범위 대비 시간 패턴/공동 변화 일치의 증가 | 목록이 바뀌었다는 사실만으로 보강 성공 |

여기서 ‘독립적인 축’은 **메타데이터 추천에 없는 연주 구분을 제공하는 보완적인 검색 축**이라는
운영상 의미다. 메타데이터와 수학적으로 완전히 독립이라는 주장을 하지 않는다.
작곡가나 유형이 같더라도, 그 안에서 다른 연주를 일관되게 구분하는 것은 추가 정보가 될 수 있다.

## 2. 비교할 메타데이터와 연주 표현

ASAP 원본에는 composer/title이 있고, 작품 유형은 기존 감사의 title/folder 규칙에서 파생했다.
570연주 중 560개에 유형이 있고 `Islamey` 10연주는 미분류다.
확인된 연주자·시대·분위기·조성 태그는 이번 입력에 없다. 파일명으로 연주자를 추정하지 않는다.
작품명/작품군은 같은 작품 제외에 사용한다. 모든 후보가 다른 작품이므로 제목 ID 일치는 검색 기준으로 유효하지 않다.

| 기준 | 거리/순위 | 역할 |
|---|---|---|
| M-C 작곡가 | 같으면 0, 다르면 1 | 작곡가 추천 축 |
| M-T 작품 유형 | 같으면 0, 다르면 1 | 유형 추천 축 |
| M-CT 작곡가+유형 | 두 불일치 지표의 평균 | **주 메타데이터 대조** |
| Q 길이·coverage | log1p(원래 beat 수), 유효 비율의 train 표준화 RMS 거리 | 데이터/길이 보조 축, 음악적 스타일로 부르지 않음 |
| M-CTQ | 정규화한 M-CT와 Q 거리 제곱의 동일 가중 평균 | 메타데이터+길이로 설명되는 효과 진단 |
| B | 기존 평균·범위 14D | **주 연주 기준** |
| B+T | B와 개별 시간 통계 57D의 거리 결합 | 시간 지식 보강 |
| B+T+R | B/T와 17쌍×7 lag 관계 119D의 거리 결합 | 관계 지식 보강 |
| CNN, BiLSTM | 기존 검증된 128D 전곡 표현의 cosine 거리 | 보조 학습 표현, 각각 모든 3 seed |

연주 표현에는 메타데이터를 섞지 않는다. 보완적인 축 자체의 동작을 먼저 본다.
B는 기존 다섯 feature 묶음 동일 가중 거리를 유지한다. T/R은 train 작품군 균형 평균·SD로
좌표를 표준화한 RMS 거리다. 각 블록 거리를 train의 다른 작품군 쌍 거리 중앙값으로 나눈 뒤
블록 제곱 거리의 동일 가중 평균을 쓴다. 차원이 많은 R이 자동으로 지배하지 않게 한다.
M-CTQ도 같은 방식으로 블록 크기를 맞춘다. scale이 0이면 해당 조건을 계산 불가로 기록한다.
검색 결과를 보고 블록 가중치·cosine 여부·K를 선택하지 않는다.

## 3. 표본과 검색 상황

현재 저장된 570연주와 검증된 export를 사용한다. 기존 작품군 분리 규칙을 유지한다.
train과 겹치는 validation 작품군, train/validation과 겹치는 test 작품군은 평가 query에서 제외한다.

- 평가 query: 기존 test 역할 중 B/T/R이 모두 유효하고 유형이 알려진 연주.
- 후보 gallery: 기존 train 역할 중 같은 공통 입력 조건을 만족하고 유형이 알려진 연주.
- 같은 작품 연주 대조를 위해 gallery의 각 작품/grid에 유효 연주가 최소 3개 있어야 한다.
  구간 cohort에서도 조건을 적용한 뒤 이 지원 수를 다시 확인한다.
- 원래 test clean/common 대상은 67연주·6작품군, train common 대상은 364연주·35작품군이다.
  이는 새 검색 실험의 최종 수가 아니다. 미분류·후보 지원·구간 조건을 적용한 수를 먼저 기록한다.
- validation은 별도 기술 결과만 보고한다. 모델/가중치 선택에는 사용하지 않는다.
- query 자신의 작품군 전체를 후보에서 제외한다. 서로 다른 작품의 beat 위치를 대응시키지 않는다.
- **주 K=5**, 보조 K=10. 후보 작품군 수가 K 미만이면 K를 줄이지 않고 그 query/K를 지원 부족으로 남긴다.
- 주 검색은 **작품군당 최대 1연주**다. 전체 연주를 거리순으로 정렬하고 이미 선택된 작품군은 건너뛴다.
  작품군 내 최적 연주를 찾는 실제 동작을 포함한다. 녹음이 많은 작품의 최소 거리 이점은 별도 대조한다.
- 보조 결과로 작품군 제한 없는 Top K도 계산하고, 녹음이 많은 한 작품이 결과를 차지하는 정도를 보고한다.

모든 비교는 같은 query와 같은 gallery를 사용한다. 방법별로 결측 후보를 따로 빼지 않는다.
전체 570개에서의 넓은 메타데이터 분포는 구성 설명용이다. 평가 6작품군의 결과를 9작곡가 전체로 확대하지 않는다.
이 split의 결과는 앞선 실험에서 이미 확인했다. 이번은 **기존 평가 자료를 재사용하는 후속 탐색 실험**이며,
완전히 새로운 최종 검증 세트라고 부르지 않는다.

## 4. 실험 A: 메타데이터와 얼마나 다른 검색 축인가?

현재 전곡 B/T/R와 고정 모델 export를 그대로 사용한다. 방법마다 후보를 새로 검색한다.
이전 파일럿처럼 대표값에서 골랐던 B/C 두 후보의 순서만 비교하지 않는다.

### 메타데이터 동점 처리

같은 작곡가/유형의 후보가 많으면 메타데이터만으로 특정 연주의 순위를 결정할 수 없다.
파일명순 Top K 하나와 비교하면 우연한 차이를 새 축의 효과로 오해할 수 있다.

- 동점 허용 오차는 1e-12, 기준은 각 tier의 첫 거리와의 차이다. 연쇄적으로 tier를 연결하지 않는다.
- 100개 고정 seed에서 후보별 무작위 우선순위를 부여한다. 모든 방법에 같은 우선순위를 적용한다.
- 각 실행에서 거리 tier 안을 우선순위로 정렬하고 작품군 제한을 적용한다.
- 평균과 5~95 percentile을 보고한다. 이 seed 범위는 모집단 신뢰구간이 아니다.
- 메타데이터 두 동점 해소 목록끼리의 겹침도 계산한다. 스타일 목록의 차이가
  메타데이터 내부의 임의 선택만으로 생기는 차이와 구분되는지 본다.

| 지표 | 정의/해석 |
|---|---|
| 연주 겹침 O | 두 Top K의 공통 연주 수 / K |
| 작품군 겹침 F | 공통 작품군 수 / K; 같은 작품의 다른 연주만 바뀐 것인지 구분 |
| 새 연주 비율 N | 1−O; 메타데이터 100회 평균 및 범위 |
| 순위 반영 겹침 | 공통 연주의 min(1/rank) 합 / Σ(1/r), rank=1..K |
| 메타데이터 구성 | 같은 작곡가·같은 유형·둘 다 같음의 비율; gallery의 가용 비율 및 M 기준과 비교 |

**낮은 겹침은 차별성의 증거이지 검색 성능 점수가 아니다.** 높거나 낮다는 이유만으로 좋은 임베딩을 고르지 않는다.
작품군은 그대로인데 연주만 바뀌었다면 ‘새 작품 발견’과 ‘작품 안의 연주 구분’을 따로 보고한다.

## 5. 실험 B: 그 차이가 스타일상 일관적인가?

같은 좌표로 검색하고 같은 거리로 채점하는 순환을 피하기 위해,
**한 연주의 서로 겹치지 않는 구간으로 검색과 평가를 나눈다.**

### 검색 구간과 평가 구간

원래 index 0부터 완전한 64-beat 블록으로 나누고 마지막 짧은 블록은 제외한다.
블록 번호 0,2,4,...가 A, 1,3,5,...가 B다. A로 검색하고 B로 평가한 뒤 방향을 바꿔 반복한다.
query와 candidate 각각 자기 곡 안에서 나눈다. 다른 작품의 A/B 위치가 같은 악구라는 가정은 없다.

- 양쪽에 7채널 공통 유효 인접 쌍 51개 이상인 64-beat 블록이 각각 최소 2개 필요하다.
- 블록 경계를 가로질러 변화량·run·lag를 계산하거나 떨어진 블록을 이어 붙이지 않는다.
- B/T/R은 검색 쪽 블록만으로 재계산한다. T/R 좌표 목록과 임계값은 기존 train 기준을 유지한다.
  T의 run은 블록 경계에서 종료한다. lag 관계는 블록 내부 유효 pair만 모아 계산한다.
- CNN/BiLSTM도 검색 쪽의 유효 64-beat 블록을 고정 checkpoint로 다시 인코딩한다.
  전곡 벡터를 그대로 넣고 일부 구간 평가를 독립 검증이라고 부르지 않는다.
- 방향별 scaling은 train gallery의 검색 쪽만으로 fit한다. 평가 측정치 scale은 train의 평가 쪽만으로 fit한다.
- 기본 정규화는 기존 작품별 공통 제거·scale을 유지한다. 이 reference는 전곡 catalog의 관측을 사용하므로
  양쪽 정보가 완전히 독립인 것은 아니다. **겹치지 않는 구간의 재현성 검사**라고 명시한다.
  새 작품 reference 없이도 적용되는 실험으로 해석하지 않는다.
- 두 방향과 모든 방법이 유효한 공통 cohort를 먼저 고정한다. 실제 수를 기록하며,
  결과가 나쁘거나 표본이 적다는 이유로 구간 조건을 완화하지 않는다.

### 평가할 스타일을 세 부분으로 나누기

평균·범위의 역할을 시간 측정치만으로 평가하지 않는다. 아래 점수는 각각 보고하며
시간/관계 정보가 모든 축에서 동시에 개선해야 한다고 요구하지 않는다.

| 평가 축 | 평가 구간에서 계산할 별도 측정치 | 계산 조건 |
|---|---|---|
| E-L 대표 성향·표현 폭 | 7채널 중앙값·IQR. Rubato 성향만 절댓값 중앙값 | 채널별 유효 beat ≥100 |
| E-T 변화 크기·구간별 분포 | 채널별 32-beat ΔRMS의 q25/q50/q75(log1p) | 32블록의 유효 인접 쌍 ≥25, 최소 3블록 |
| E-R 공동 변화 | 64-beat Tempo–Dynamics Δ상관의 q25/q50/q75와 population SD | 유효 pair ≥51, 두 변화량 SD>1e-12, 최소 2블록 |

상수 신호의 ΔRMS=0은 정의된 값이다. E-T는 국소 변화 크기의 분포를 검사하며,
악구 순서나 모든 시간 패턴을 검증하는 점수는 아니다. 방향 반전·지속 길이는
계산 가능한 채널과 연주 수를 공개한 보조 진단으로만 추가한다. 주 점수 대신 사용하지 않는다.
E-R의 주 pair는 Tempo–Dynamics다. 나머지 비파생 pair는 지원 수를 표시한 보조 분석이며 주 pair를 바꾸지 않는다.
평가 좌표는 train 작품군 균형 평균·SD로 표준화한다. E-L/E-T는 다섯 feature 묶음 동일 가중,
Pedaling 하위 채널은 묶음 안에서 평균한다. E-R은 네 좌표의 RMS 거리를 쓴다.
상수 좌표는 train에서만 제외하고 목록을 저장한다. 남는 좌표가 없으면 해당 축은 계산 불가다.

같은 MIDI/feature 정의에서 만든 수치 proxy이며 사람의 스타일 정답은 아니다.
입력과 평가 측정치가 관련되는 것은 의도한 것이지만, 사용한 beat와 정확한 요약 좌표를 복사하는 평가는 피한다.
잔차의 상승을 원래 crescendo나 accelerando로 바로 해석하지 않는다.

### 점수와 조건부 대조

후보 c의 평가 거리 d를, 같은 query의 전체 gallery 평가 거리 분포에서 백분위로 바꾼다.
**S(q,c)=P[d(q,무작위 후보)>d(q,c)]+0.5P[동점]**이다. 무작위 후보는 작품군→작품→연주를
동일 가중으로 고른다. 큰 S가 더 잘 맞는 것이며 Top K의 평균을 S@K로 보고한다.
무작위 후보 기대값 0.5는 이 점수에만 해당한다. Top K 겹침의 무작위 기대값은 50%가 아니다.

1. **일반 무작위 목록:** 같은 gallery에서 작품군을 균등하게 K개, 작품/연주를 균등하게 선택한다.
2. **메타데이터 목록:** M-C/M-T/M-CT/M-CTQ와 비교한다. 주 대조는 M-CT다.
3. **같은 작품 대조:** 검색한 K개 후보의 작품·grid를 그대로 두고, 그 안에서 연주만 무작위로 바꾼다.
   query와 후보 작품 관계가 같은 상태에서 특정 연주를 고른 의미를 검사한다.
   선택 연주가 같은 작품의 나머지 연주보다 가까운 비율도 동점 0.5로 보고한다. 작품별 ≥3연주가 필요하다.
4. **메타데이터·길이 조건부 섞기:** gallery에서 composer×type×길이 quartile×coverage bin 안의
   연주 key에 검색 벡터를 재배정하고 다시 검색한다. 평가 벡터는 그대로 둔다.
   길이는 log1p beat 수의 train 가중 quartile, coverage는 [0,.8),[.8,.95),[.95,1]이다.
   전체 결합 벡터를 함께 섞어 B/T/R 내부 관계를 보존한다. singleton/동일 작품 내 교환만 가능한 비율을 공개한다.
   검색에 기여한 연주의 80% 미만이 교환 가능하면 이 대조는 지원 부족이다. 같은 작품 대조를 대체하지 않는다.

무작위·같은 작품 대조는 100 seed, 조건부 섞기는 100 seed를 사용한다.
검색 자체를 다시 수행하며 좋은 후보 목록을 유지한 채 거리만 바꾸지 않는다.
실험 B의 모든 baseline, shuffle, 예시는 같은 구간 cohort에서 다시 검색한다.
실험 A의 전체 cohort에서 얻은 novelty와 실험 B의 일부 cohort 점수를 합쳐 한 성공률로 만들지 않는다.
B cohort에서도 겹침·새 후보 비율을 다시 계산한다.
실험 B는 전곡 벡터의 Top K를 그대로 채점한 것이 아니라, 같은 검색 방식을 일부 구간에서 검증한 결과다.
따라서 B에서 성공하더라도 A의 모든 전곡 추천 후보가 검증됐다고 말하지 않는다.

## 6. 주 비교와 결론 규칙

| 사전에 정한 주 비교 (K=5) | 스타일 평가 | 목적 |
|---|---|---|
| B vs M-CT | E-L | 평균·범위의 전반적 성향/폭 검색 역할 |
| B+T vs B | E-T | 시간 지식 보강의 검색 역할 |
| B+T+R vs B+T | E-R | 공동 변화 지식 보강의 검색 역할 |

모든 비교의 E-L/E-T/E-R를 함께 공개하되 보조 축의 개선으로 주 비교를 바꾸지 않는다.
CNN/BiLSTM은 모든 seed 평균·최소~최대로 보고하며 가장 좋은 seed를 선택하지 않는다.

- **차별성만 관찰:** 겹침/작품 구성은 달라졌지만, 다른 구간 스타일 일치가 대조보다 좋아지지 않음.
- **작품 선택 효과:** 전체 S@K는 좋아졌지만 같은 작품의 다른 연주 대비 이점은 없음.
- **보완적인 연주 축의 근거:** 메타데이터 동점까지 고려한 차별성을 기술하고, 주 스타일 축에서 M-CT보다
  높은 S@K와 같은 작품 연주 대조보다 높은 일치를 함께 관찰. M-CTQ와 조건부 섞기 결과도 지지하는지 확인.
- **지식 보강의 근거:** 해당 주 비교의 스타일 S@K가 늘고, 새로운 후보에서도 일치가 유지되는지 보고.
  ‘새 후보’의 평가는 동점 seed별 메타데이터 목록 밖 후보로 계산하며, 새 후보가 3개 미만인 query는 지원 부족이다.
  새 후보 점수 자체를 주 전체 점수 대신 선택하지 않는다.
- 차별성 크기는 연속값으로 공개한다. 임의의 겹침 임계값을 넘겼다는 이유로 독립성/성공을 확정하지 않는다.
- 주 점수의 양의 평균 차이뿐 아니라 아래 짝지은 구간의 하한도 0보다 높을 때 개선 근거로 보고한다.
  구간이 0을 포함하거나 대조와 구분되지 않으면 긍정적 평균이 있어도 불확실한 관찰로 남긴다.

query 내 두 방향·동점 seed를 먼저 평균 → 작품 → 작품군 평균으로 집계한다.
같은 query 작품군을 짝지어 2,000회 bootstrap한다. 5작품군 미만이면 구간 대신 작품별 결과만 보고한다.
주 비교 세 개의 S@K 차이는 보수적으로 각 **98.33% percentile 구간**을 보고한다.
6작품군처럼 작은 평가 표본과 고정 gallery의 한계가 있어 모집단 전체에 대한 확증으로 부르지 않는다.
seed 반복은 평가 작품 수를 늘리지 않는다. gallery가 공유되는 의존성도 남는다.

## 7. 후보 수·길이 효과와 재현성

- 길이/coverage 차이와 반환 작품의 녹음 수를 기록하고 Q 및 M-CTQ와 비교한다.
- 후보가 많은 작품의 최소 거리 이점을 보기 위해, gallery 작품군당 3연주를 작품 균형으로 추출한
  동일 gallery 20회를 모든 방법에 적용한다. 3연주 미만 작품군은 이 보조 분석에서 제외하고 support를 저장한다.
- 학습 모델 추가 학습, test 기반 가중치 탐색, 좋은 작품/seed만 선택하는 작업은 하지 않는다.
- 결과 전에 입력 hash, 원본 정규화 provenance, split, query/gallery, 좌표 목록, 구간 mask와 지원 수를 고정한다.
- 합성 입력으로 metadata 동점, 동일 벡터, 반대 변화, 구간 교차 경계, 결측, 조건부 교환,
  K 지원 부족과 연주/작품군 겹침 구분을 검증한다. 실제 결과는 별도 구현으로 순위·점수를 재계산한다.

## 8. 산출물과 구현 순서

1. `cohort.csv`, `availability.csv`, `partition_manifest.csv`, `scales.json`, `preflight.json`:
   query/gallery·축별 지원·메타데이터 동점 수·교환 가능 비율을 점검하고 고정한다.
2. `neighbors.csv`: experiment, view, method, model_seed, tie_seed, query, rank, candidate, piece/family, distance.
3. `overlap.csv`, `metadata_exposure.csv`: 연주/작품군 차이와 각 메타데이터 기준 비교.
4. `style_scores.csv`, `controls.csv`, `per_work_metrics.csv`, `bootstrap.csv`:
   스타일 축별 점수, 대조와 같은 작품 내부 일치, 주 비교 및 지원 부족.
5. 그림: 메타데이터별 겹침 heatmap / 메타데이터 내부 임의 선택 범위 / 차별성과 스타일 일치의 2축 그림 /
   보강 전후 스타일 축별 변화 / 작품별 결과 / 미리 정한 query의 두 검색 목록과 held-out profile.
6. 재현 CLI, 입력·코드·출력 hash와 독립 검증. 큰 구간 캐시는 저장소 밖 `datasets/`에 둔다.

예시는 성능순으로 고르지 않는다. eligible test query를 작품·key 이름순 정렬해 첫 query를 주 예시로 고정하고,
전체·작품별 결과를 함께 제공한다. 실행 전 preflight에서 support가 없으면 그 사실부터 보고한다.

중간 발표에서 보여줄 문장은 결과에 따라 달라진다. 기대하는 결론은
“메타데이터와 다른 연주를 가져오면서, 별도 구간에서도 정의한 스타일에 더 잘 맞는다”이며,
근거가 없으면 “검색 결과는 달라지지만 그 차이의 스타일상 의미는 아직 확인되지 않았다”로 보고한다.
