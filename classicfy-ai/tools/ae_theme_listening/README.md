# 기준 A와 같은 작품의 두 후보 X/Y 청취

저장소 루트에서 다음을 실행하고 <http://localhost:8766/>을 연다.

```sh
python3 classicfy-ai/tools/ae_theme_listening/serve.py
```

`classicfy-ai/`에서 실행할 때는 `python3 tools/ae_theme_listening/serve.py`, 이 도구 폴더에서는
`python3 serve.py`를 사용한다. 서버는 자신의 파일 위치를 기준으로 자료를 제공한다.

총 **10문항·20작품·30녹음**이다. 한 문항의 X/Y만 같은 작품이며 문항 간 작품 중복은 없다.
상단 번호나 이전/다음 버튼으로 이동한다.
한 번씩 들을 때 발췌 재생 합계는 약 19분이며 반복·메모 시간은 별도다.

1. ‘A 구간 재생’으로 삽입 플레이어에서 주제 구간을 듣는다. 외부 재생 제한 안내가 있으면 ‘A 원본 듣기’를 이용한다.
2. X와 Y도 같은 방식으로 듣는다. 삽입 재생에는 구간 자동 종료와 반복 선택이 적용된다.
3. A와 연주 스타일이 더 비슷하게 들린 쪽을 고른다. ‘둘이 비슷함’, ‘판단 어려움’도 가능하다.
4. ‘선택 저장하고 임베딩 결과 보기’를 누르면 내 선택과 실제 A–X/A–Y 거리를 비교한다.

선택 전에는 거리·모델 순위·가까움/멀음 표시·카드의 후보 연주자 정보와 재생 시간을 숨긴다.
선택을 먼저 저장한 뒤 해당 사례의 결과 JSON을 불러온다. X/Y는 브라우저마다 무작위 배치하고
재방문 시 유지한다. 결과 공개 후에는 선택을 바꾸지 않는다. 단축키 `1`(A), `2`(X),
`3`(Y)은 각 삽입 구간 재생을 시도한다. 원본 링크는 별도로 제공한다.
설치나 확장 다운로드는 필요 없다. 원본 페이지에서는 종료·반복을 직접 조작한다.
모델 결과·구간·녹음이 동일한 문항만 이전 응답·메모·시간 수정과 X/Y 순서를 승계한다.
처음 두 문항은 그대로 유지했다. 교체된 문항의 기존 응답은 별도 보관해 JSON 내보내기에
포함하며 새 점수에서는 제외한다. 이전 브라우저 저장본도 보존한다.

## 연주 선정과 결과

기준 A에서 다른 작품 전체를 검색해 가장 가까운 연주 B를 고른다.
그다음 **B와 같은 작품의 다른 녹음 중 A와의 거리가 가장 먼 C**를 고른다.
C의 선정 기준은 B와의 거리가 아니다. B/C는 같은 악보 버전·동일한 주제 마디를 사용한다.
전체 corpus 2,801연주와 최종 epoch 100 모델을 사용하며 영상 상태에 따라 재정렬하지 않는다.

- 더 가까운 후보 선택: ‘임베딩과 일치’.
- 더 먼 후보 선택: ‘임베딩과 반대’.
- 둘이 비슷함/판단 어려움: 별도로 기록하고 확정 선택 일치율의 분모에서 제외.

거리는 전곡의 8마디 임베딩을 평균한 cosine 거리다. 발췌 주제만의 거리는 아니다.
주제/주제 악구는 음악 형식 분석·연주 해설과 해당 MusicXML을 대조해 수동 지정했다.
일부는 주제 전체가 아닌 첫 문장이나 동기만 발췌했으며 카드에 표시한다.
[주제 근거와 생성 절차](../../analysis/ae_theme_listening/README.md).

## 재생과 저장

`player.js`는 공식 YouTube IFrame API의 `loadVideoById({videoId,startSeconds,endSeconds})`로
지정 구간을 재생한다. 반복을 켜면 구간 끝에서 같은 범위를 다시 로드하고, 끄면 멈춘다.
별도 다운로드·설치·음원 추출을 하지 않으며 연주 속도를 바꾸지 않는다.
삽입 플레이어는 버튼을 누를 때만 생성하고, 다른 연주를 재생하면 이전 플레이어를 일시정지한다.
문항 이동 시 플레이어와 타이머를 제거한다. 브라우저 자동 재생 제한은 별도 안내한다.
`controls=0`으로 공식 플레이어의 시간 막대를 표시하지 않고 재생·일시정지는 바깥 버튼으로 제공한다.
영상 영역과 YouTube 표시는 가리지 않으며, 제목/연주자가 보일 수 있다.
HTTP 서버 origin과 `strict-origin-when-cross-origin` Referrer-Policy를 사용한다.

**반드시 `localhost` 주소를 사용한다.** 2026-11-04 같은 영상·플레이어·브라우저에서
`http://127.0.0.1:8766`은 오류 150, `http://localhost:8766`은 실제 재생으로 확인됐다.
두 요청 모두 실제 origin에 맞는 Referer를 전달했고, IP 주소에서 기본 컨트롤·구간 없는 재생·
공식 privacy-enhanced 호스트로 바꿔도 같은 오류가 났다. localhost에서는 **30개 모두 실제 재생**을 확인했다.
따라서 이전 IP 주소에서의 29개 실패를 영상 자체의 모든 사이트 재생 금지로 해석하지 않는다.
YouTube 내부의 세부 호스트 판정 규칙은 확인되지 않았다. 원본 녹음이나 임베딩 선정은 바꾸지 않았다.
[실제 검사와 조건 비교](../../analysis/ae_theme_listening/embed_playback_checks.json),
화면용 상태는 `embed_checks.js`에 보관한다. 재생 결과는 시점·브라우저·계정·지역에 따라 달라질 수 있다.

기존 `127.0.0.1` 진입 주소는 localhost로 자동 이동한다. 주소별로 localStorage가 다르므로,
이 앱의 응답 저장 키만 로컬 서버의 일회성 POST로 복사한다. 서버는 응답 내용을 파일에 저장하지 않는다.
이전 주소의 저장본은 삭제하지 않으며 무관한 브라우저 저장 키는 옮기지 않는다.
localhost에 이미 응답한 저장본이 있으면 유지하고 충돌 사본은 별도 보관한다.
localhost에 응답이 없고 이전 주소에 응답이 있으면 이전 응답을 사용하고 기존 빈 저장본을 보관한다.
충돌 사본은 JSON 내보내기의 `origin_storage_backups`에 포함하며 점수에 합산하지 않는다.

청취 화면의 구간 시작·종료·길이는 선택 전 기본 비공개이며 선택 후 공개한다.
‘재생 문제 확인용 시간 표시’를 켜면 시간 조정이 가능하고, 표시 이력은 다시 꺼도 응답에 남긴다.
변경한 시간은 삽입 플레이어에 바로 적용한다. 원본 페이지에는 시작 시각 링크만 적용되며,
기존 탭의 재생 위치나 원본 페이지의 시간 표시를 청취 화면에서 변경하지 않는다.
원본에서 종료 시각을 확인하려면 시간 표시를 켠다. 들리는 템포 차이나 악구 길이 자체는 숨기지 않는다.

시간은 MIDI 정렬 기준 추정값이며 영상 오프셋은 청음 확인 전이다.
어긋나면 시간 표시를 켜고 카드의 ‘재생 시간 조정’으로 수정한다.
원본 시작 링크는 초 단위로 내림하며, 삽입 플레이어는 소수 초 경계를 API에 전달한다.
실제 시작은 YouTube의 keyframe 처리에 영향을 받을 수 있다.
원본 YouTube 페이지와 글꼴에 인터넷을 사용한다.
YouTube 내부에는 연주자·영상 제목이 표시될 수 있어 연주자 신원까지 숨기는 완전 맹검은 아니다.
이전 IP 주소의 외부 플레이어에서 오류 150을 확인해 원본 페이지로 전환했던 이력이 있다.
[YouTube 오류 안내](https://developers.google.com/youtube/iframe_api_reference#onError)에 따르면
150은 영상 소유자의 외부 재생 불허(101과 동일)를 뜻한다. 원본 링크는 종료를 자동 제한하지 않는다.
2026-11-04 Safari에서 첫 사례의 세 원본 재생 상태를 확인했다. 두 번째 사례의 한 원본은
재생 불가여서, 같은 앨범 트랙의 UMG 공식 업로드로 재생 링크를 교체하고 재생 상태를 확인했다.
[교체 근거와 확인 기록](../../analysis/ae_theme_listening/source_replacements.json).
`study.js`의 고정 매핑은 재생 URL에만 적용하고 `data.js`의 원본 출처는 보존한다.
이 재생 URL 교체 자체는 임베딩·선정 연주·pack ID·저장된 X/Y 순서와 응답을 바꾸지 않는다.
문항 재구성은 새 pack으로 저장한다. 재생 중인 영상의 주제 경계는 아직 미검수다.
10문항에서 사용하는 30개 영상은 공개 watch 페이지의 재생 가능 응답·videoId 일치·오디오
형식 정보를 백그라운드로 확인했다. [검사 기록](../../analysis/ae_theme_listening/background_checks.json).
전체 30개의 실제 삽입 재생 상태는 별도 무음 headless Chrome에서 확인했다. 주제 경계를 청음 검수하지는 않았다. 후보 세 영상 중 불가 응답이
있는 문항은 선정하지 않았으며, B/C의 모델 순위를 재정렬하지 않았다.
화면·자료는 정적 파일이므로 소스를 조사하면 결과를 미리 볼 수 있다. 접근 통제를 위한 도구는 아니다.

응답·X/Y 순서·시간 수정은 pack ID별로 브라우저에 저장한다. localhost 주소 전환 시 복사에만
로컬 서버를 거치며 외부 응답 서버로 전송하지 않는다.
‘응답·임베딩 비교 JSON 저장’으로 사본을 보관할 수 있다. 결과 파일 오류가 나도 최초 선택을
유지하고 다시 불러온다. 원본을 열었다는 기록과 ‘구간을 들었어요’라는 사용자 확인을 별도로 저장한다.
새로 제출한 응답에는 원본 재생 URL과 시간 표시 이력, 삽입 재생 이벤트·오류·반복 설정도 남긴다.
원본에서 시간을 숨겼거나 구간 전체를 실제 청취했다는 증거로 해석하지 않는다.
표시한 구간을 실제로 전부 들었는지는 자동 판정하지 않는다.
이전 화면의 단순 1–5 유사도 메모는 이 선택 실험의 응답으로 변환하지 않는다.

## 재생성 및 검증

```sh
.venv/bin/python classicfy-ai/scripts/prepare_ae_theme_listening.py --stage build
node --test classicfy-ai/tools/ae_theme_listening/study.test.cjs classicfy-ai/tools/ae_theme_listening/player.test.cjs
cd classicfy-ai
PYTHONPATH=src ../.venv/bin/python -m unittest tests.unit.tools.test_ae_theme_listening tests.unit.tools.test_ae_theme_listening_server -v
```

`--stage all`은 모델 추론부터 수행하며 hash가 같은 chunk를 재사용한다. 원본 corpus/모델은
저장소 밖 기존 `Classicfy/diagnostics/`, metadata는 `Classicfy/datasets/`에 필요하다.
`analysis/ae_theme_listening/listening.json`은 모델 역할·거리가 포함된 진행자 자료이고,
초기 화면의 `data.js`에는 그 정보가 없다. `results/<case>.json`은 제출 후에만 요청한다.

`?qa=1`은 UI 동작 확인용 별도 저장 공간이다. `is_test: true`로 표시하며 실제 청취 응답과
구분한다. 이 모드의 합성 선택은 인간 청취 결과로 사용하지 않는다.
